## Layout

```
src/                 UI: React Native + Expo Router
  app/               screens (tabs, add, apps, QR)
  lib/               Xray config, subscriptions, storage, updates, live data
modules/xray-vpn/    local Expo module in Kotlin
  XrayVpnService     VpnService: TUN, per-app rules, notification
  XrayVpnModule      bridge to JS: start, ping, apps, rules, updates
  VpnTileService     quick settings tile
core/                Go package xraybridge: Xray inside the app
scripts/             core build and emulator check
docs/                this site (docsify)
```

- **Tunnel.** `XrayVpnService` opens the TUN and hands its descriptor to Xray's own `tun`
  inbound through `env.xray.tun.fd`, so there is no separate tun2socks. The app itself is left
  out of the tunnel.
- **Core.** `core/` (xraybridge) is built by `gomobile bind` together with libXray into one AAR.
  It runs Xray in the app's process and reports observatory delays, the balancer's target and
  its override, traffic counters, and HTTP requests through a chosen outbound. No local ports
  are opened.
- **Balancer.** Each server is an outbound `s-<id>` behind balancer `main` (`leastPing` or
  `roundrobin`); the observatory tests servers every 30 seconds. Picking a server sets the
  balancer override, with no restart.
- **Rules.** `geoip.dat` and `geosite.dat` are downloaded into `files/geo` and passed through
  `xray.location.asset`.

## Building

```bash
npm ci
scripts/build-libxray.sh             # needs Go, the Android SDK and NDK
npx expo prebuild --platform android
cd android && ./gradlew assembleRelease
```

Checks:

```bash
npx tsc --noEmit && npx expo lint && npx jest --ci
(cd core && go vet ./... && go test ./...)
```

## CI and releases

`.github/workflows/android.yml` checks the code, builds the APKs (arm64-v8a, armeabi-v7a, and
x86_64 for the emulator) and launches the app on an API 34 emulator.

To release, use **Actions → Android → Run workflow** with a version. The workflow stamps the
version and `versionCode`, signs the APKs with the `ANDROID_KEYSTORE_B64` and
`ANDROID_KEYSTORE_PASSWORD` secrets, and creates tag `v<version>` and a release with the
arm64-v8a and armeabi-v7a APKs and `SHA256SUMS`. The app finds updates through this
repository's latest release.

Versions follow the [We1ssBoard](https://github.com/WeIbSchatten/We1ssBoard) panel: a client
release shares the panel's `MAJOR.MINOR` (panel 1.9.x → clients 1.9.x), and patch versions are
independent, so a client fix does not need a panel release. The workflow checks this with
`scripts/check-version-series.sh` before building and refuses any other version.
