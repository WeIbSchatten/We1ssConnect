---
title: Маршрутизация
description: Правила маршрутизации на роутере — списки сервисов, пресеты, домены, подсети и удалённые списки; куда отправлять трафик и группы серверов.
---

Правило говорит, **что** (сервисы, домены, подсети) и **куда** отправлять. Правила проверяются
сверху вниз, срабатывает первое подходящее; порядок меняется перетаскиванием строк.

## Куда отправлять

| Действие | Что происходит |
| --- | --- |
| **Через туннель** | через «Авто», группу серверов или конкретный сервер |
| **Через интерфейс роутера** | через уже настроенный на роутере VPN: WireGuard, AmneziaWG, OpenVPN и другие |
| **Напрямую** | мимо туннеля, адреса узнаются через DNS для прямых сайтов (по умолчанию Яндекс) |
| **Блокировать** | сайт не открывается, DNS-запрос отклоняется |

## Что включать в правило

- **Сервисы** — списки сообщества [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains):
  YouTube, Telegram, Discord, Meta, X, TikTok, Google AI, «Заблокированное в России»,
  «Российские сервисы из-за границы» и другие. Списки обновляются сами. Для сервисов, чьи
  приложения ходят по IP (Telegram, Discord, Meta, X, Cloudflare и др.), роутер подгружает и их
  подсети.
- **Пресеты** — «Российские сайты и IP» (домены `.ru`, `.su`, `.рф`, список `category-ru` и
  российские IP) и «Реклама и трекеры» (`category-ads-all`). Те же списки, что в приложении.
- **Категории** — `geosite:…` и `geoip:…`, как в Xray и v2rayN (подробнее ниже).
- **Домены** — по одному в строке; домен включает и все свои поддомены.
- **IP-адреса и подсети** — например `149.154.160.0/20`.
- **Удалённые списки** — ссылки на rule-set sing-box (`.srs`, `.json`) или на простые текстовые
  списки доменов и подсетей. Поддерживаются строки вида `example.com`, `*.example.com`,
  `domain:example.com`, `DOMAIN-SUFFIX,example.com`, адреса и подсети, комментарии через `#`.
- **Протоколы** — трафик, который sing-box распознаёт как `bittorrent`, `quic`, `stun` и т. п.
  Чаще всего — торренты напрямую в режиме «весь трафик»: в режиме «по спискам» в sing-box
  попадает только трафик из правил «через туннель», так что торренты и так идут напрямую.

## Категории

Категории — те же, что в файлах `geosite.dat` и `geoip.dat` для Xray: `geosite:ru-blocked`,
`geosite:youtube`, `geosite:category-ads-all`, `geoip:ru`, `geoip:telegram` и сотни других. sing-box на
роутере не читает `.dat`, поэтому роутер берёт те же данные из
[runetfreedom/russia-v2ray-rules-dat](https://github.com/runetfreedom/russia-v2ray-rules-dat), где каждая
категория опубликована отдельным rule-set `.srs`, и обновляет их сам. Это те же файлы, что использует
приложение на телефоне и компьютере, так что названия совпадают.

Категории можно писать в поле **Категории** или прямо в полях **Домены** и **IP-адреса и подсети**.
Категории с атрибутами (`geosite:google@cn`) не поддерживаются. Если категории нет, она пропускается,
а на обзоре появляется предупреждение. Подсети категорий `geoip:` в правилах «через туннель» роутер
тоже перехватывает, чтобы через туннель шли и приложения, которые подключаются по IP.

## Правила текстом

Кнопка **Текстом** над правилами показывает их одним списком. Его можно править, вставить из
заметок или перенести на другой роутер. Кнопка **Формой** возвращает обычный вид. Оба вида правят
одни и те же правила.

```
default: direct
protocol(bittorrent)->direct

# Заблокированные домены в РФ
domain(geosite:ru-blocked)->proxy
domain(geosite:refilter)->proxy

# Реклама
domain(geosite:category-ads-all)->block

# Сайты
domain(shikimori.io)->proxy(Финляндия)
geoip(telegram)->proxy
```

| Условие | Что совпадает |
| --- | --- |
| `domain(example.com)` | домен и поддомены |
| `domain(geosite:ru-blocked)` | категория доменов |
| `geoip(telegram)` | категория адресов |
| `ip(149.154.160.0/20)` | адрес или подсеть |
| `service(youtube)` | сервис из списка |
| `preset(ru)` | пресет (`ru`, `ads`) |
| `list(https://…)` | удалённый список |
| `protocol(bittorrent)` | протокол: `http`, `tls`, `quic`, `stun`, `dns`, `bittorrent`, `dtls`, `ssh`, `rdp`, `ntp` |

Действия: `direct` — напрямую, `proxy` — через «Авто», `proxy(Имя)` — через группу или сервер с
этим именем, `block` — блокировать, `vpn(wg0)` — через интерфейс роутера.

- `default: direct` — режим «по спискам», `default: proxy` — «весь трафик».
- Строка с `#` называет правила под ней; комментарий пишется только на отдельной строке.
- `!` в начале строки выключает правило, не удаляя его.
- Ошибки подсвечиваются под текстом с номером строки, и пока они есть, сохранить нельзя. Если
  категории нет в файлах правил, появится предупреждение.

## Как это работает

В режиме **по спискам** роутер отвечает на DNS-запросы к доменам из правил «через туннель»
служебными адресами из диапазона `198.18.0.0/15` (FakeIP). Соединения к ним и к подсетям из
правил перехватываются и уходят в sing-box, который знает, какой домен за каким адресом
стоит. Остальной трафик идёт мимо sing-box вовсе — роутер не тратит на него ресурсы.

В режиме **весь трафик** перехватывается всё, кроме локальной сети, а домен узнаётся из
самого соединения.

## Группы серверов

Группа — свой маленький «Авто» из части серверов: например, только финские. Направьте правило
на группу, и этот сервис всегда будет идти через одну страну. В группу попадают серверы из
выбранных подписок, отмеченные вручную, и можно отфильтровать их по названию регулярным
выражением (`finland|helsinki`).

## Списки и GitHub

Списки скачиваются с GitHub раз в сутки (меняется в настройках). Если GitHub у провайдера
заблокирован, включите **Настройки → Списки и подписки → Скачивать списки через туннель**.
