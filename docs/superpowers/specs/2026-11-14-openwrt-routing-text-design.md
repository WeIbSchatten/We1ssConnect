# OpenWrt: маршрутизация текстом

Дата: 2026-11-14 · Статус: черновик на согласование

## Зачем

Владелец настраивает маршрутизацию на роутере длинным списком правил: geosite-категории РФ,
реклама, обновления Windows, отдельные сайты. В нынешней форме LuCI каждое правило — окно с
десятком полей: долго заводить, трудно читать целиком, нельзя скопировать список с одного
роутера на другой или из заметок. Нужен текстовый вид, где весь маршрут читается и
правится как один список:

```
default: direct
protocol(bittorrent)->direct

# Заблокированные домены в РФ
domain(geosite:ru-blocked)->proxy
domain(geosite:refilter)->proxy

# Рекламные домены
domain(geosite:category-ads-all)->block
```

## Цели

- На странице «Маршрутизация» переключатель «Формой / Текстом». Оба вида правят одни и те
  же правила; переключение туда и обратно ничего не теряет.
- Текстом выражается всё, что умеет форма правил: сервер или группа, VPN-интерфейс,
  сервисы, пресеты, категории, домены, подсети, удалённые списки, выключенное правило.
- Новое условие `protocol(...)` (в первую очередь bittorrent) — в службе и в обоих видах.
- Ошибки видны в редакторе до сохранения, с номером строки.

## Не цели

- Текстовый формат в телефонном и настольном приложениях.
- Группы серверов и правила устройств в тексте — они остаются в своих разделах.
- Доменные префиксы Xray `full:`/`keyword:`/`regexp:` — правило роутера их не понимает и сейчас.

## Анти-цели (провал, даже если «работает»)

- Сохранение текста меняет или теряет правила, которые пользователь не трогал.
- Старые настройки, заведённые формой, перестают работать или требуют миграции.
- Опечатка в тексте молча выключает маршрут: правило без ошибки пропадает.

## Подходы

| | Как | Плюсы | Минусы |
|---|---|---|---|
| **А (выбран)** | Текст — второй вид тех же uci-секций `rule`; разбор и сборка в браузере | Служба и хранение не меняются, нет миграции, подсветка ошибок на месте | Новая возможность правил должна попасть в оба вида |
| Б | Текст хранится одним полем, разбирает служба | Один редактор, комментарии как есть | Миграция старых правил; разбор дважды (служба + браузер) |
| В | Только импорт/экспорт | Дёшево | Не то, что просили: повседневная работа остаётся в форме |

Выбран **А**: ничего не ломает у тех, кто уже настроил правила, а текст становится полноценным
способом их править.

## Синтаксис

Строка — одно из:

- пустая — разделитель блоков;
- `# текст` — комментарий (только на всей строке);
- `default: direct` или `default: proxy` — режим (`main.mode` = `selective` / `global`);
  не больше одной такой строки; без неё режим не меняется;
- правило: `[!]условие(значение)->действие[(цель)]`. Пробелы вокруг `->` и скобок допустимы.
  `!` в начале — правило выключено (`enabled 0`).

Условия (по одному на строку):

| Текст | uci | Значение |
|---|---|---|
| `domain(example.com)` | `domain` | домен, покрывает поддомены |
| `domain(geosite:ru-blocked)` | `category` `geosite:…` | категория доменов |
| `geoip(telegram)` | `category` `geoip:…` | категория адресов |
| `ip(149.154.160.0/20)` | `subnet` | адрес или подсеть, IPv4/IPv6 |
| `service(youtube)` | `service` | ключ из `w1.SERVICES` |
| `preset(ru)` | `preset` | ключ из `w1.PRESETS` |
| `list(https://…)` | `remote_list` | URL удалённого списка |
| `protocol(bittorrent)` | `protocol` (новое) | протокол, который распознаёт sing-box |

Действия: `direct`, `block`, `proxy` (цель «Авто»), `proxy(Имя)` — группа или сервер по
имени, `vpn(wg0)` — интерфейс. Цель можно указать и идентификатором: `proxy(group:<sid>)`,
`proxy(server:<id>)` — сборка пишет его, когда имя неоднозначно или содержит `)`.
Порядок поиска имени: группа, затем сервер; совпадение точное, с учётом регистра.

Протоколы — то, что sing-box распознаёт при sniff: `http`, `tls`, `quic`, `stun`, `dns`,
`bittorrent`, `dtls`, `ssh`, `rdp`, `ntp`. Другое значение — ошибка.

## Текст ↔ uci-секции

**Разбор.** Блок — подряд идущие строки комментариев и правил до пустой строки или до
следующего комментария после правил. Комментарии над правилами блока, склеенные через пробел,
становятся `name` правил этого блока. Внутри блока подряд идущие строки с одинаковыми
(вкл/выкл, действие, цель/интерфейс) сливаются в одну секцию; смена любого из них начинает
новую секцию с тем же `name`. Порядок секций = порядок строк.

Слияние внутри секции не меняет поведения: у её условий одно действие, а sing-box получает
их отдельными правилами подряд.

**Сборка.** Для каждой секции по порядку: если у неё есть `name` и он отличается от `name`
предыдущей секции — пустая строка (кроме самой первой) и `# name`; затем по строке на
каждое условие в порядке: protocol, service, preset, category, domain, subnet, remote_list.
Первой строкой — `default: …` по `main.mode`.

**Свойство, которое держат тесты:** `текст → секции → текст` после первой нормализации
не меняется, и `секции → текст → секции` даёт те же секции (с точностью до `.name` uci).

**Сохранение** (кнопка «Сохранить и применить» LuCI): при ошибках разбора сохранение
блокируется. Иначе все секции `rule` удаляются и создаются заново в порядке текста,
`main.mode` пишется, если в тексте есть `default:`. Группы, устройства и прочие настройки не
трогаются.

**Переключение.** Форма → текст собирает текст из текущих (в том числе ещё не сохранённых)
значений uci. Текст → форма возможен только без ошибок: разобранные секции кладутся в uci
так же, как при сохранении, но без применения.

## Проверки в редакторе

- Синтаксис, неизвестное условие или действие, неизвестный сервис/пресет/протокол, имя цели,
  которого нет, неоднозначное имя, плохой домен/подсеть/URL/категория — ошибка со строкой,
  сохранение блокируется.
- Несуществующая категория (как `geoip(wattpad)`): при сохранении редактор проверяет
  категории по `CATEGORY_BASE` (HEAD на `.srs`); 404 — предупреждение со строкой, сохранение
  не блокируется (сеть роутера или браузера может быть недоступна). *Решение исполнителя
  проекта, можно убрать.*
- `protocol(…)->proxy` при `default: direct` — предупреждение: в выборочном режиме в туннель
  попадает только трафик, совпавший с доменными/адресными правилами, и такое правило почти
  ничего не поймает.

## Служба на роутере

- `config.uc`: правило читает `list protocol`, проверяет по тому же списку протоколов,
  неизвестный — ошибка `rule <name>: bad protocol <p>`.
- `singbox.uc`: условие `{ protocol: [...] }` с действием правила, как остальные; в DNS-правила
  не идёт. Правило с одним только protocol считается правилом туннеля для проверки
  «ни одно правило не отправляет трафик в туннель» только при `proxy`/`vpn`.
- Форма получает поле «Протоколы» (`ChecklistValue`), чтобы оба вида оставались равны.

## Где код

- Разбор и сборка — новый модуль LuCI `we1ssconnect/rules.js` рядом с `common.js`, без
  зависимостей от DOM, чтобы его можно было гонять в Node.
- Вид «Текстом» — в `view/we1ssconnect/routing.js`: textarea моноширинным шрифтом, список
  ошибок и предупреждений под ним.
- Строки интерфейса — в `openwrt/i18n/ru.json` (правка инструментом Edit, отступ 1 пробел),
  затем `node openwrt/i18n/i18n.mjs …`.

## Тесты

- Модуль `rules.js` — юнит-тесты в Node (`node --test`) с минимальной подменой `baseclass`
  LuCI: пример владельца целиком, каждое условие и действие, выключенное правило, имена с
  `)` и дубли, ошибки со строками, оба свойства обратимости. Запуск — в CI openwrt.
- `config_test.uc` / `singbox_test.uc` — `protocol` доходит до правила sing-box; плохой
  протокол — ошибка.
- `luci-e2e.mjs` — переключиться на «Текстом», вставить пример владельца (без wattpad),
  сохранить, вернуться в форму и увидеть правила; сгенерированный конфиг sing-box содержит
  `protocol: ["bittorrent"]` и rule-set `geosite-refilter`.
